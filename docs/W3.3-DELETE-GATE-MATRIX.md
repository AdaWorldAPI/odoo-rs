## What "the gate" actually is (two categories, not one)

W3.3 deletes `surreal_ast` + `triple` + native `ToSql` emit once the shared path
provably covers what the native path emits. But the native path emits **two kinds
of DDL**, and the OGAR doctrine treats them oppositely:

- **Structural DDL** (`DEFINE TABLE`/`FIELD`) — the shared emitter
  `ogar_adapter_surrealql::emit_surrealql_ddl` must byte-cover it. Almost done.
- **Behaviour DDL** (`DEFINE FUNCTION`/`EVENT`, computed `VALUE`/`READONLY`) — the
  SurrealQL-AST-trap **forbids** behaviour→DDL (`surreal_ast.rs:1-10`,
  OGAR-TRANSPILE-SUBSTRATE.md:526 "Behaviour flows producer → `Class`+`ActionDef`
  → adapter; never producer → DDL"). So the gate for these rows is **not** emitter
  byte-parity — it is **carrier completeness**: the facts the native DDL stubbed
  must be provably carried by `ActionDef`/`KausalSpec`/`ComputedField`, and a
  consumer must consume them, so deletion loses no wiring.

## The verdict — minimal ordered checklist to flip every delete-blocking row

The blocker is **not** "grow the SurrealQL emitter" (that would re-add behaviour→DDL,
which the trap forbids). It is "carry the behaviour arm through the substrate to a
consumer." Ordered, each a falsifiable acceptance test:

1. **AT-STRUCT-1 (residual type fidelity, #5).** OGAR `map_type_to_surrealql`
   (`adapter/lib.rs:658`) maps `"any" → "any"`. Test: shared emit of a `Kind::Any`
   field contains `TYPE any;` byte-identical to native `surreal_ast.rs:95`.
2. **AT-STRUCT-2 (polymorphic, #8; low priority).** OGAR emits a multi-target
   Many2one as unquoted `record<a|b>`. Test: shared emit of a union-target
   association == native `record<a|b>` byte-identical (not backtick-wrapped).
3. **AT-CARRY-1 (compute carrier, #10/#11).** `compile_source(src)` exposes
   `lift_model_graph_python`'s `Class.computed_fields` (`vocab:224`) non-empty for
   an Odoo `compute=`/`store=True` field. Test: for `account.move.amount_total`,
   `compile_source(SRC)[i].class.computed_fields` contains `{field:"amount_total",
   compute_method, stored:true}`.
4. **AT-CARRY-2 (function inventory, #15).** `CompiledClass` (or a sibling of
   `compile_source`) surfaces `lift_actions` output (`ogar-from-ruff/lib.rs:534`).
   Test: for slice_2, `|ActionDefs|` == `|native Schema.functions|` (same method
   set native emits as `DEFINE FUNCTION`), matched by `predicate`+`object_class`.
5. **AT-CARRY-3 (reactive+guard carrier, #16/#17).** Every native `DEFINE EVENT`
   maps to an `ActionDef` with the right `KausalSpec`. Test: for each cross-record
   `@api.depends` in slice_2, an `ActionDef.kausal == Depends{paths}` carries the
   dep paths; for each `_check_*` guard, an `ActionDef.kausal ∈ {StateGuard,
   LifecycleTrigger}` + a `guard_failure_policy`.
6. **AT-CONSUME (delete-safety).** A consumer (an `od-posting`-shaped adapter or
   the `emit_rust`/`emit_python` codegen leg, OGAR-TRANSPILE-SUBSTRATE.md:447-464)
   consumes AT-CARRY-1/2/3 so the reactive wiring native DDL stubbed is not lost.
   Test: the wiring facts round-trip through the consumer (no `DEFINE FUNCTION`/
   `EVENT`/`VALUE` fact present in native emit is absent from the carrier set).

Only when AT-STRUCT-1..2 and AT-CARRY-1..3 + AT-CONSUME are green does Stage C
delete `surreal_ast` + `triple` + native `ToSql`. Structural rows (#1-9, #13) are
already covered; #12/#14/#18 are dormant (never populated by the corpus path).
